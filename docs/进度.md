已实现。现在 **`progress_index` 直接表示 0–100 的百分比**，speckle_sync 可以直接拿来画进度条。

## 进度对照表

| 步骤 | `progress` | `progress_index` |
|------|------------|------------------|
| ① 收到 POST /upload | `接收` | **1** |
| ⑤ /upload 返回 ret=0 | `入队` | **5** |
| ⑦ Revit Execute 开始 | `执行` | **6** |
| ⑨ RVT 打开完成 | `打开` | **9** |
| ⑩ 开始 Speckle 转换 | `准备` | **10** |
| ⑪ 遍历图元（解析） | `解析` | **10 + ⌊当前/总数×40⌋**，上限 50 |
| ⑬ Operations.Send（上传） | `上传` | **50 + ⌊已上传/估算总数×40⌋**，上限 90 |
| ⑭ Send 完成 | `提交` | **91** |
| ⑯ 最终回调 is_final=true | `完成` | **100** |

### 公式示例

**解析**（你的例子）：
```
500 / 10000 → 10 + floor(500/10000 × 40) = 10 + 2 = 12
```

**上传**（解析结束后从 50 起算，避免进度回退）：
```
估算总数 = max(已转换图元数 × 10, 当前已上传数)
进度 = 50 + floor(已上传 / 估算总数 × 40)，上限 90
```

上传阶段 Speckle 序列化对象数远大于图元数，且上传前不知道精确总数，所以用 `图元数×10` 作为初始估算，随已上传数动态调大。

## speckle_sync 侧用法

```text
直接用 progress_index 显示进度条（0–100）
仅当 is_final=true 且 progress=完成 时推送远端结果
```

进度**单调递增**，不会回退。

## 上报频率

- 解析/上传：每 **500** 个上报一次（首尾也会报）
- **时间心跳（方式 D）**：默认每 **30 秒**强制上报一次（即使未到 500），避免慢模型长时间无进度更新
  - 环境变量：`SPECKLE_UPLOAD_PROGRESS_HEARTBEAT_SECONDS`（默认 30）
- `progress_index` 为 0–100 百分比，单调递增
